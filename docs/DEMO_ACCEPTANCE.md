# Demo acceptance

Run one must start from a real failing test, use current-state data, use durable memory, make a candidate change in isolated compute, rerun tests, produce Snyk evidence, obtain a Gatekeeper decision, and perform a controlled GitHub effect only when authorized.

The successful run must create a Learning Event and a Rote reusable procedure.

Run two must present the same failure class on a different component. It must demonstrate reusable procedure or memory reducing rediscovery while still refreshing current state, security evidence, and Gatekeeper authorization.

A HOLD or DENY must visibly prevent the GitHub effect. An authority timeout, malformed response, stale digest, or mismatched action must fail closed.

The demo is complete only when sponsor participation is visible and load-bearing rather than decorative.
